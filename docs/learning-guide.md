## 每节的教学流程

1. **先看业务问题** —— 从一笔具体交易和数据变化出发，不上来罗列抽象接口。
2. **推导设计** —— 直接写会遇到什么问题、如何逐个拆解、引入的模式有什么代价。
3. **对照代码** —— 结合原文、对应章节分支和用户真实实现；明确类、方法与 SQL 的调用关系。
4. **IDEA 跟读与验证** —— 给出断点、输入前提和观察判据；不捏造运行输出，不默认执行会污染现有数据的测试。
5. **自测与验收** —— 先独立回答和定位代码，再对照参考分析；不通过则补当前节，不提前开下一节。

后续教学不再沿用旧草案中“其余留给自读”的限制；讲解深度以用户能解释具体业务与实现为准。
