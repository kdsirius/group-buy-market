# 带练教程规则

## 适用范围

覆盖 `docs/study/`，与根规则叠加生效；局部冲突以本文件为准。

## 局部差异

- 先读 `../learning-guide.md` 的当前状态，再读原文和对应分支，最后核对用户当前实现。
- 教程文件名沿用 `{作者学习序号}-{小节号}-{标题}.md`；合并复习使用 `00-截至2-12-拼团业务串联复习.md`。覆盖范围与下一节位置读取学习指南，不在本文件另记进度。
- 每节先用具体业务场景提出问题，再推导直接写法的不足、逐步改造及当前代码；说明收益和代价。复习课不要求重复实现，按现有代码恢复设计过程。
- 使用中文口语解释；术语第一次出现给大白话，Java/Spring 知识嵌在对应业务步骤旁。关系图使用真实类名。
- 内容包含：能力目标、原文映射、IDEA 定位与观察点、业务/库表变化、设计推导、验证、自测、小结、对照参考及下一节留下的问题。
- 真实输出与教学推演分开标注。未运行的业务验证只能写观察步骤及预期判据；静态风险只能写推演，不能声称复现。
- 本地教程不是复制原文；仅摘必要小片段，优先引用当前工程方法。讲解片段不加落盘标记；真正让用户手敲的完整代码块前紧邻 `**文件**：` 加仓库相对路径。
- 验收题先给不含答案的题目，再独立放参考分析，避免用户只能照着复述。口述需能定位到具体代码与 SQL。
- 简历只描述已实现且能验证解释的能力；明确学习项目来源，不编造生产规模、性能提升或本人独立原创。

## 本区域的验证方式

- 检查相对链接、代码路径、类名、方法名、章节边界、金额和计数推演。
- 对需要写入工程的代码块，从文档抽取到项目外累积副本后验证，不能维护独立“验证版”。
- 复习课若无落盘代码，代码抽取不适用；仍核对现有工程构建，机制探针只在仓库外运行，并明确不能替代业务集成测试。
- 进度状态记录在 `../learning-guide.md`，教程中仅保留本节验证证据；写完教程不等于学习者已验收。
