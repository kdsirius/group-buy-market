# 带练教程规则

## 适用范围

覆盖 `docs/study/`，与根规则叠加生效；局部冲突以本文件为准。

## 局部差异

- 先读 `../learning-guide.md` 的当前状态，再读原文和对应分支，最后核对用户当前实现。
- 教程文件名沿用 `{作者学习序号}-{小节号}-{标题}.md`；合并复习使用 `00-截至2-12-拼团业务串联复习.md`。覆盖范围与下一节位置读取学习指南，不在本文件另记进度。
- 原文和参考分支用于核对章节范围与行为，不沿用原文的讲述难度；面向初学者，用尽量短的篇幅讲清一条主线，扩展内容按需展开。
- 前端已获用户授权由 AI 实现，不要求手敲；前端讲义只挑必要的请求构造、响应处理与页面渲染代码，讲清前后端契约，不展开样式/DOM基础长教程。后端仍按用户手敲带练。
- 每新增一块代码，紧邻说明“现在缺什么 → 直接写会怎样 → 为什么拆成这个类 → 怎样验证”，让用户看见自己也能推导的过程，而不只是给最终结构。
- 按可手敲的依赖顺序交付：先创建被引用的类型/上下文，再写使用方，最后回填组装方法；阶段性文件给出完整可编译版本，不让用户长时间依赖尚不存在的类。
- 交付代码带必要中文注释：类说明业务职责，接口方法说明用途、关键参数/返回口径及副作用；实现解释数据来源与这样写的原因，避免隔一段时间无法回读。不以重复代码字面的注释凑数量。
- 不再要求用户手敲纯教学/替身练习测试。优先给真实接口/集成验证的逐步操作、数据前提、预期结果与副作用；需要新增测试时，必须能长期保护具体业务或回归缺陷，解释其价值。代理可在项目外用替身验证，但不把它冒充真实集成证据或强制学习作业。
- 测试指导按“准备什么 → IDEA/接口工具点击哪里 → 输入什么 → 预期现象 → 为什么 → 失败看哪里”，不能只列测试目标；未隔离数据前不执行写库测试。
- 使用中文口语解释；术语第一次出现给大白话，Java/Spring 知识嵌在对应业务步骤旁。主动用 Mermaid 展示业务与调用/数据流，节点使用真实类名；每张图下面紧接白话解释起点、箭头和关键分支。图不能清楚呈现时再选合适配图，不为凑图增加理解负担。
- 内容包含：能力目标、原文映射、IDEA 定位与观察点、业务/库表变化、设计推导、验证、自测、小结、对照参考及下一节留下的问题。
- 真实输出与教学推演分开标注。未运行的业务验证只能写观察步骤及预期判据；静态风险只能写推演，不能声称复现。
- 本地教程不是复制原文；仅摘必要小片段，优先引用当前工程方法。讲解片段不加落盘标记；真正让用户手敲的完整代码块前紧邻 `**文件**：` 加仓库相对路径。
- 验收题先给不含答案的题目，再独立放参考分析，避免用户只能照着复述。口述需能定位到具体代码与 SQL。
- 简历只描述已实现且能验证解释的能力；明确学习项目来源，不编造生产规模、性能提升或本人独立原创。

## 本区域的验证方式

- 检查相对链接、代码路径、类名、方法名、章节边界、金额和计数推演。
- 对需要写入工程的代码块，从文档抽取到项目外累积副本后验证，不能维护独立“验证版”。
- 复习课若无落盘代码，代码抽取不适用；仍核对现有工程构建，机制探针只在仓库外运行，并明确不能替代业务集成测试。
- 进度状态记录在 `../learning-guide.md`，教程中仅保留本节验证证据；写完教程不等于学习者已验收。
