# 协作约定

- 用户以学习理解和后续简历表达为目标，不要直接代写后端业务；后端先写教程，用户手敲，AI 读真实文件后验收。
- 用户已授权前端页面与交互由 AI 直接实现；前端不要求手敲样式，验收后只讲关键请求、响应、渲染链路。
- 每节流程是：教程 → 用户实现和真实验证 → AI 审阅 → 用户修订 → 明确通过/欠账并停下 → 用户自行提交 Git → 用户确认提交后才开下一节。
- **一会话一节**：用户希望每节独立会话，方便跨Agent与会话接手；收尾更新唯一学习指南、长期约定，提供各仓库commit message与下一会话提示词，然后停止。下一Agent先读文档并核对Git，不依赖旧聊天或临时验证目录。
- **用户验证确认**：用户明确确认已完成真实复验时，据此记为用户确认并保留代理未亲验范围；不因没有重新上传截图反复索要同一批材料或重开已验收章节。新失败或证据矛盾再针对性调查。
- Git只读：add/commit/push、切分支与合并等写操作均由用户执行；AI仅提供准确命令与提交说明，不把要求commit message当成授权提交。
- 不主动使用子 Agent；确有必要先征求用户同意。
- 商城对接只在用户单独建库的 `E:\dev\java\group-buy-market\s-pay-mall-market` 开展；原 `E:\dev\java\group-buy-market\s-pay-mall` 是独立已完成项目，对代理仅有只读权限，不修改其中任何代码、配置、文档或 Git 状态。这样隔离是为避免污染原商城；编写拼团对接教程时以新副本真实文件为准，不能仅因目录改名就假定模块名、数据库或运行环境已隔离。
- 原文和参考仓库只用于核对范围与行为，不照搬讲法；本地教程要独立、短、适合初学者。
