# 教学风格约定

- 每新增代码先说“缺什么、直接写有什么问题、为什么放在这里、如何验证”。
- 代码要有职责注释：类说明业务职责，接口方法说明参数/返回口径和副作用；实现注释说明业务原因，不重复字面代码。
- 不再要求用户手敲纯学习/替身测试。优先真实接口、IDEA 调试、数据库前后查询；新增测试必须长期保护业务或回归具体缺陷。
- Mermaid 用于表达业务流、调用流和数据流；每张图紧跟白话解释起点、箭头、分支和数据变化。需要时可用浏览器验证前端，但不为凑图增加复杂度。
- 前端教程只讲 API 请求、响应映射、渲染和错误处理；页面样式由 AI 实现，真实接口验证要区分前端演示与后端事实。
- 浏览器页面操作、前端联调和自动化验证统一使用 `ego-browser` Skill；开始浏览器任务前先运行 `ego-browser skill` 读取当前版本用法，并复用同一 TaskSpace。
- 每个前端章节仍必须有 `docs/study` 学习文档：只讲关键代码和前后端契约，不要求用户手敲样式；验证分为 AI 用 ego-browser 实跑一遍，以及用户按步骤在自己的 IDEA/浏览器/接口环境再跑一遍，分别记录证据。
- 验证汇报严格区分：通过、失败、跳过、未运行；完整构建失败不能写成代码失败，用户自测不能写成代理亲验。
